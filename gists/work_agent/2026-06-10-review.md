# MountWizzard4 – Code & Architecture Review

**Date:** 2026-06-10 (updated 2026-10-08 against the current code base)
**Scope:** `src/mw4` (logic, gui, base, mountcontrol)
**Dimensions reviewed:** PySide6 / Qt6 usage, Pythonic style, architecture,
simplicity, performance, maintainability.

> This document is an assessment with prioritized recommendations. It does **not**
> change any code. Findings reference concrete files and symbols so they can be
> acted on directly.
>
> **Update 2026-10-08:** every finding was re-checked against the current code.
> Each section carries a status (**Resolved**, **Partly resolved**, **Open**). Most
> original recommendations have been implemented; the open items are listed in
> section 8.

---

## 1. Executive Summary

MountWizzard4 is a mature, well-structured desktop application. The codebase shows
a deliberate architecture: a clean separation between business logic
(`src/mw4/logic`) and the GUI (`src/mw4/gui`), a centralized device registry, a
consistent worker/thread-pool pattern, and pervasive type annotations. The Qt6
migration to PySide6 is consistently applied.

Since the first review the GUI-thread-blocking sleep helper, the `app: Any` seams,
the magic status numbers, the misplaced docstrings and the `# pragma: no cover`
markers have been removed, and `mountcontrol` was restructured (typed parent context,
split `ObsSite`, slimmer `MountDevice`). Remaining areas for improvement are the
**central signal hub** on the application object (smaller and mostly typed now), the
**`parent: Any` seams in the device sub-objects**, a **test hook in the production
constructor**, and the local nested event loops of the native-Qt dialogs.

**Overall maturity rating:** Strong (4 / 5, trending up).

| Dimension          | Rating | Short note                                              |
|--------------------|:------:|---------------------------------------------------------|
| PySide6 / Qt6      |  4/5   | Idiomatic signals/slots & thread pool; typed signals    |
| Pythonic style     |  5/5   | Type hints everywhere; conventions followed             |
| Architecture       |  4/5   | Clean layering; typed contexts; app still a signal hub  |
| Simplicity         |  4/5   | Data-driven registry/status code; smaller classes       |

## 2. Strengths

- **Clean layer separation.** `src/mw4/logic` holds device logic; `src/mw4/gui`
  holds presentation. Tabs are decoupled from each other and communicate through
  the application object, honoring the "no direct dependencies between GUI tabs"
  rule.
- **Worker / thread-pool pattern.** [`base/tpool.py`](../../src/mw4/base/tpool.py)
  provides a clean `Worker(QRunnable)` with `WorkerSignals` (`finished`, `error`,
  `result`) and robust traceback formatting. This is the right Qt idiom for
  offloading work from the GUI thread.
- **Centralized device registry.**
  [`base/deviceRegistry.py`](../../src/mw4/base/deviceRegistry.py) implements the Python
  mapping protocol (`__getitem__`, `__contains__`, `__iter__`) so `dReg["camera"]`
  and `"camera" in dReg` read naturally. Config collection/writing is driven by
  dataclass `fields()`, which is elegant and DRY.
- **Dataclass-based device config.** e.g. `DeviceConfigIndi` in
  [`base/indiClass.py`](../../src/mw4/base/indiClass.py) — typed, defaulted, and
  serialization-friendly.
- **Single cyclic timing source.**
  [`base/timeManager.py`](../../src/mw4/base/timeManager.py) drives all periodic work
  from one 100 ms `QTimer` and fans out via signals (`update1s`, `update10s`, …).
  This avoids a proliferation of independent timers. The mount timer connections are
  made in one place, `MountDevice.connectTimers()`.
- **Typed application surface.**
  [`base/appProtocol.py`](../../src/mw4/base/appProtocol.py) (`AppProtocol`) types the
  application object for devices, windows and tabs; `mountcontrol` has its own
  `MountContext` protocol
  ([`mountcontrol/mountContext.py`](../../src/mw4/mountcontrol/mountContext.py)).
- **Focused `mountcontrol` modules.** `MountStatus` enum (`mountStatus.py`), an
  `AngleProperty` descriptor (`angleProperty.py`), command mixin
  (`obsSiteCommands.py`), derived data (`mountData.py`) and combined power /
  connectivity / clock handling (`mountTimeConnectivity.py`).
- **Consistent type annotations and camelCase naming**, matching the project
  conventions, and a strict test/coverage culture (`pyproject.toml`).
- **Modern tooling.** Ruff (with `UP`, `SIM`, `C` complexity, isort), pytest-qt,
  pytest-cov, pyrefly, `uv` build backend, Python 3.12–3.14
  (`requires-python = ">=3.12,<3.15"`). Ruff selects `E`, `T2`, `UP`, `I`, `C`, `LOG`, `W`,
  `SIM`, `A`, `RUF`, `B`, `BLE`.

## 3. PySide6 / Qt6

### 3.1 Blocking the GUI event loop — `mainThreadSleep` (was High) — **Resolved**

`base/threadUtils.py` and `mainThreadSleep` no longer exist, and nothing in `src/mw4`
uses `time.sleep` or a sleep-style nested loop any more. The remaining
`QApplication.processEvents()` calls are in `gui/extWindows/splashScreen.py` and
`gui/utilities/pyqtgraph/gPlotBase.py`.

**New low-priority note:** the native-Qt dialog wrappers
(`qtMessageDialog.py`, `qtFileDialog.py`, `qtInputDialog.py` in
`gui/utilities/nativeQt/`) run a local `QEventLoop` so call sites such as
`MWFileDialog.getOpenFileName(...)` stay synchronous. This is the standard modal-dialog
idiom and is intended, but it shares the re-entrancy characteristics described above;
keep new code from calling them while cyclic updates mutate the same widgets.

### 3.2 Central signal hub on `MountWizzard4` (Medium) — **Partly resolved**

[`mainApp.py`](../../src/mw4/mainApp.py) now declares 24 signals (not ~40): the timer
signals moved to `TimeManager` (`update0_1s` … `update30m`), and the earlier
`material` / `gameABXY` signals are gone. The hub still exists
(`msg`, `redrawHemisphere`, `showImage`, `refreshModel`, …) and is reached through
`self.app.<signal>`, but it is now described by `AppProtocol`, so the contract is
explicit. Device signals live in subsystem-owned objects
(`MountSignals`, `base/signalsDevices.py`).

**Remaining recommendation:** group the GUI/redraw signals into small signal objects
(e.g. hemisphere, model, satellite) only if the coupling becomes a problem; the
protocol already narrows the dependency surface.

### 3.3 Untyped signal payloads (Low/Medium) — **Mostly resolved**

On the application object nearly all payloads are typed
(`msg = Signal(int, str, str, str)`, `playSound = Signal(str)`,
`showImage = Signal(Path)`, `operationRunning = Signal(int)`,
`updateSatellite = Signal(Time, GeographicPosition)`, …). `object` remains where the
payload is genuinely heterogeneous or not worth a type: `sendSatelliteData`,
`WorkerSignals.result`, `ModelRun` status signals (`statusExpose/Solve/Slew`),
`photometryFinished`, `videoBase.pixmapReady`, `keypadW.imgChunk`,
`signalsDevices.azimuth/result`.

### 3.4 Positive Qt notes

- `Worker.setAutoDelete(False)` plus explicit `worker*` references avoids the
  classic "C++ object deleted while running" crash — good.
- `closeEvent` calls `threadPool.waitForDone(10000)` before teardown — correct
  shutdown ordering.

## 4. Architecture

### 4.1 `app` passed as `Any` everywhere (Medium) — **Mostly resolved**

`AppProtocol` (`base/appProtocol.py`, `@runtime_checkable`, type-only imports so no
import cycles) is now used throughout: no `app: Any` / `mainW: Any` is left in
`src/mw4`, tabs take `mainW: "MainWindow"`, and devices take `app: AppProtocol`.
The `mountcontrol` sub-objects take a `MountContext` protocol instead of `parent: Any`.

**Remaining:** the device sub-objects in `logic/` (`focuserIndi`, `cameraIndi`,
`cameraSGPro`, `telescope*`, `lightPanel*`, `dome*`, `keypad`, `fileHandler`, …) still
take `parent: Any`; about 150 `Any` annotations remain in `src/mw4` overall. A small
protocol per device family would remove most of them.

### 4.2 GUI reaching deep into the domain model (Medium) — **Resolved**

`MountStatus` (`IntEnum`, `mountcontrol/mountStatus.py`) with `STATUS_LABELS`
is the single source of truth for status codes, and `ObsSite` exposes
`isTracking`, `isStopped`, `isParked`, `isFollowingSatellite` and `statusText()`.
`MainWindow.updateStatusGUI` iterates over `(widget, obsSite.isX)` pairs; no magic
status numbers remain there. Device access via `self.app.dReg["mount"]` is still
common, which is the intended registry pattern.

### 4.3 Addon registry pattern (Positive) — **Resolved**

[`mainWindowAddons.py`](../../src/mw4/gui/mainWindow/mainWindowAddons.py) builds a
`dict[str, TabAddon]`. The `TabAddon` base class
(`gui/mainWaddon/tabAddon.py`) declares `initConfig`, `storeConfig`, `setupIcons`,
`updateColorSet` and `shutdown` as no-op hooks, so the dispatcher needs no
`hasattr` guards.

### 4.4 Constructor-as-orchestrator (Low) — **Partly resolved**

`MountWizzard4.__init__` (`mainApp.py`, 138 lines in total) is still a linear
sequence (thread pool, queue, registry, config, window, timers) but is now structured
with `#` comments instead of fake docstrings and delegates configuration to
`initConfig()` / `storeConfig()`. Splitting into `setupThreadPool` / `setupDevices` /
`setupMainWindow` is optional.

**Test hook still present:** `MountWizzard4(test: int = 0)` connects
`timeMgr.update10s` to `mainW.close` in production code. (The earlier
`hasattr(app, "mount")` branch in `DeviceRegistry` is gone; the registry takes an
optional `mount: MountDevice | None` argument, which is proper dependency injection.)

### 4.5 `mountcontrol` structure (new) — **Resolved**

Result of the `mountcontrol` refactoring (see `PLAN_mountcontrol_refactor.md`):

- `MountTime` became `MountTimeConnectivity`; power (`bootMount`, `shutdown`),
  reachability / round-trip probing and clock sync are combined in one class.
- `MountContext` protocol replaces `parent: Any`; `Geometry` and
  `MountTimeConnectivity` no longer reach into `parent.app`.
- `ObsSite` shrank from 726 to 295 lines: `MountStatus` → `mountStatus.py`,
  13 angle properties → `AngleProperty`, command methods → `ObsSiteCommands` mixin.
- `MountDevice`: derived values moved to `MountData`; all timer connections are made
  in `connectTimers()`; `data` is a property delegating to `MountData`.
- Residual: `pyrefly` still reports errors in `mountcontrol/convert.py` and
  `geometry.py` caused by skyfield `Angle` typing (`reify`).

## 5. Pythonic Style & Conventions

### 5.1 Misplaced "docstrings" in `mainApp.py` (Medium) — **Resolved**

The no-op string expressions in `MountWizzard4.__init__` were converted to `#`
comments.

### 5.2 `# pragma: no cover` violates project rules (Medium) — **Resolved**

`grep -rn "pragma: no cover" src` returns nothing (including `logic/camera/camera.py`).

### 5.3 Repetitive `if/else` blocks (Low) — **Resolved**

`MainWindow.updateStatusGUI` now loops over a tuple of
`(widget, obsSite.isX)` pairs and `deviceStatGui` / `smartTabs` mappings drive the
other status updates.

### 5.4 Naming nuance (Informational) — unchanged

The instructions mandate camelCase for "classes, modules and variables." Standard
Python uses `CapWords` for classes (which the code does) and `snake_case` for
functions/variables. The project deliberately overrides PEP 8 here; that is a
valid project choice but worth noting for new contributors so it stays consistent.

## 6. Simplicity & Maintainability

- **Long configuration dicts in constructors** — **Open (low)**: `slewSpeeds`
  (`tabMount_Move.py`), `smartTabs` and `deviceStatGui` (`mainWindow.py`) are still
  built in `__init__`; they depend on widgets, so moving them is optional.
- **`DeviceRegistry.addDevices`** — **Resolved**: a `deviceSpec` table of
  `(name, factory, deviceType, isConfigurable)` is iterated in a loop; adding a device
  is a one-line change.
- **Magic numbers** — **Resolved**: the status line uses `self.app.MAX_THREAD_COUNT`.
- **Test concerns in production code** — **Partly resolved**: `DeviceRegistry`
  accepts an injected `mount`; the `test: int` parameter of `MountWizzard4` remains
  (see 4.4).

## 7. Performance

- The single 100 ms tick fanning out to cyclic signals is efficient and avoids
  timer sprawl — good. Slots on `update0_1s` (10 Hz) should stay cheap; this has not
  been re-profiled.
- **Resolved:** `updateThreadAndOnlineStatus` (1 s) now only builds the status text.
  The Skyfield `dark_twilight_day` evaluation and `shutil.disk_usage` run in
  `updateTwilightAndDisk`, connected to `update30s` (and once on first use).
- **Resolved:** the nested-event-loop sleep (3.1) no longer exists.

## 9. Closing Note

The codebase is in good shape and the main findings of the first review have been
addressed: no nested-event-loop sleep, no `pragma: no cover`, typed application and
mount contexts, enum-based mount status, data-driven registry and status code, and a
leaner `mountcontrol` package. The remaining work is incremental: typing the device
sub-objects in `logic/`, removing the production test hook, and trimming the
application signal hub.
