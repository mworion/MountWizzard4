## 2. Architecture

### 2.1 Strengths
- Clear layering `base` → `logic`/`mountcontrol` → `gui`; no `QtWidgets`/`QtGui` or
  `mw4.gui` imports found in `logic`, `base` or `mountcontrol`.
- `DeviceRegistry` + `DeviceEntry` give a uniform device lifecycle
  (`initConfig`/`storeConfig`/`startDevices`/`stopDevices`).
- Central `TimeManager` for cyclic updates instead of many scattered `QTimer`s.
- Generic worker infrastructure (`base/tpool.py`) with a per-worker mutex that prevents
  overlapping runs of the same job.
- Driver abstraction (INDI / ALPACA / ASCOM / SGPro / NINA) via common base classes
  (`AlpacaAscomCommon`, `DriverData`).

## 3. Threading / Concurrency

| # | Sev | Location | Finding |
|---|-----|----------|---------|
| T1 | H | `src/mw4/base/tpool.py:120-128` and `:80-82` | `worker.mutex.tryLock()` is executed in the calling (GUI) thread, `worker.mutex.unlock()` in the pool thread (`Worker.run` → `finally`). Qt documents that unlocking a `QMutex` from a different thread than the one that locked it is an error / undefined behaviour. It works today with the futex implementation but is not guaranteed. Use a thread-agnostic primitive (`threading.Lock`, a `QSemaphore(1)`, or an atomic "busy" flag) instead. |
| T2 | M | `src/mw4/base/tpool.py:115-126` | When an existing worker is reused, new `resultMethod`/`finishedMethod` arguments are silently ignored (only `args`/`kwargs` are replaced). Callers passing different callbacks on subsequent calls get the old ones. Either document or assert. |
| T3 | M | `src/mw4/base/alpacaAscomCommon.py:42,63,69,86,105` | `propertyExceptions` (plain `list`) is appended from the communication loop thread and read by other callers; membership test is O(n). Use a `set` and keep it thread-confined or protected. |
| T4 | M | `src/mw4/logic/camera/cameraSGPro.py:68-92` | Busy-wait loops `while self.parent.exposing and "..." not in self.data...: time.sleep(0.1)` have no timeout. If SGPro stops updating `Device.Message` (crash, disconnect) the worker thread spins until the user aborts; with `MAX_THREAD_COUNT = 30` a few stuck workers can starve the pool. Add a deadline. |
| T5 | M | `src/mw4/gui/mainWindow/mainWindow.py:171` | `closeEvent` blocks the GUI thread up to 10 s in `threadPool.waitForDone(10000)`; afterwards it continues regardless, so still-running workers may emit signals into destroyed Qt objects. Signal stop to long-running loops first and consider shorter, staged waits. |
| T6 | L | `src/mw4/logic/powerswitch/kmRelay.py:151`, `base/sgproClass.py:142` | `time.sleep` in workers – acceptable in pool threads, but not interruptible on shutdown. Prefer `threading.Event.wait()` like in `AlpacaAscomCommon`. |

## 4. Mount Communication (`mountcontrol`)

| # | Sev | Location | Finding |
|---|-----|----------|---------|
| M1 | H | `src/mw4/mountcontrol/obsSite.py:511-524` | `parsePointing` checks the number of chunks, but not the number of comma-separated fields: `responseSplit[0..7]` and `response[4].split(",")[1..4]` raise `IndexError` on a truncated/garbled answer. The exception escapes to `Worker.run` and is only logged as critical; polling state stays half-updated. Validate `len(responseSplit)` before assignment. |
| M2 | H | `src/mw4/mountcontrol/obsSite.py:553-560` | `parseSetTargetResponse` accesses `response[0][0:2]` and `response[0][2]` **before** the `len(response) != 4` check and without checking `len(response[0]) >= 3` → `IndexError` for short answers. Reorder checks. |
| M3 | M | `src/mw4/mountcontrol/firmware.py:54-58`, `obsSite.py:734` | Same pattern: direct index access on responses without length validation. |
| M4 | M | `src/mw4/mountcontrol/connection.py:334,358,377,413,463` | `except (OSError, Exception)` / `except (OSError, ValueError, TypeError, Exception)` – listing `Exception` makes the specific types meaningless and hides programming errors (e.g. `AttributeError`) as "socket error". Catch the concrete expected exceptions; let the rest reach the worker's error path. |
| M5 | M | `src/mw4/mountcontrol/connection.py:417-419` | `decode("ASCII")` raises `UnicodeDecodeError` for any non-ASCII byte besides `0xDF`; it is outside the `try` block (in `else`) and therefore escapes `receiveData`. Use `errors="replace"` or move into the guarded block. |
| M6 | M | `src/mw4/mountcontrol/connection.py:430-442` | A new `QTcpSocket` is created, connected and aborted for every command (connect timeout 10 s). This adds latency to every poll and many TIME_WAIT sockets on the mount; with 10+ concurrent pollers a hung mount blocks up to 10 workers for 10 s each. Consider a persistent, serialized connection or at least a shorter connect timeout. |
| M7 | L | `src/mw4/mountcontrol/connection.py:463-468` | `communicateRaw` returns the literal string `"Exception"` as value – callers cannot distinguish it from a real response. |
| M8 | L | `src/mw4/mountcontrol/mount.py:74,94` | `self.mountIsUp: bool = False` assigned twice in `__init__`. |

## 5. Device Drivers / Logic

| # | Sev | Location | Finding |
|---|-----|----------|---------|
| D1 | H | `src/mw4/base/alpacaAscomCommon.py:62-110` | Any exception – including transient `OSError`/timeouts – permanently blacklists the property/method in `propertyExceptions` for the lifetime of the object. If e.g. `Connected` times out once, `connectDevice()` and the disconnect detection in `runnerCommunicationLoop` stop working until restart. ## 9. Recommended Priorities

1. **Correctness (H):** T1 (cross-thread mutex unlock), D1/D2 (ALPACA/ASCOM blacklisting and
   missing disconnect), M1/M2 (response parsing), C1 (log level config).
2. **Robustness (M):** M4/M5 (exception handling & decoding in `Connection`), T4 (timeouts in
   SGPro loops), T5 (shutdown sequence), R1 (test teardown).
3. **Tooling:** P1/P2 consistency, extend Ruff rules (`B`, `BLE`, `ANN`), add a type checker.
4. **Architecture (longer term):** A1/A2 reduce `app`/`DeviceEntry` reach-through, A4/A5
   move protocol and model logic out of GUI mixins, A8 shared framework-device base class.
