The runtime data (`finals*`, `de440_mw4.bsp`) is **needed offline**: `mainApp` loads

files are an offline fallback and must stay in the package.

## Goals

1. Stop new weight: no generated or large binary files in future commits.
2. Make clones cheaper **without** rewriting published history unless the maintainer agrees.
3. Remove duplicates in `HEAD` (tests vs. assets).
4. Document the data-asset policy so it stays that way.

## Rules

- **No history rewrite** (`git filter-repo`) as part of the normal steps. It changes every
  commit hash, breaks forks/PR links and tags (`4.0.0b*`). Only Step 6, only with explicit
  maintainer approval and a backup mirror.
- Runtime assets stay inside the wheel (offline start must work).
- Test data stays reproducible; tests must not need network access.

## Steps

### 1. Guard rails (cheap, do first)

- `../.gitignore`: add `/gists/`, `/.idea/` (check), `/.import_linter_cache/`, `/dist/`,
  `/work_agent/`, `*.coverage`, `.DS_Store`. (`gists/` currently shows up as untracked noise.)
- Add `src/mw4/resource/resources.py` (and any generated `*_rc.py`, `main_ui.py` if generated
  at build time – check first, `gui/widgets` is tracked today) to `../.gitignore` if they are
  regenerated by `tasks.py`.
- CI check (ubuntu lint job): fail when a newly added file in a PR is larger than 1 MB
  (`git diff --name-only --diff-filter=A origin/main... | xargs du -k`), with an allow-list
  file `.github/large-files-allowlist.txt` for intended assets.
- Add a `pre-commit` hook `check-added-large-files --maxkb=1024` (same limit).

### 2. Deduplicate `HEAD`

- `tests/testData/{finals2000A.all,finals.data,de440_mw4.bsp}`: point the tests at
  `../src/mw4/assets/data` (fixture `dataPath`) instead of keeping copies. Saves ~6.5 MB and
  removes a drift risk. Check tests that write to the data dir – they must copy to `tmp_path`.
- Verify with `git ls-files | xargs sha1sum | sort | uniq -w40 -d` that no other
  byte-identical duplicates exist.

### 3. Slim the test images

- `star1/2/3.fits` and `m51.fit` are 17.5 MB each. Options, in order of preference:
  1. Crop to the region the tests use (e.g. 1024² px, ~2 MB) and regenerate the expected
     values; keep one full-size file only if a test needs the full sensor.
  2. Store as compressed FITS (`.fits.fz`, tile compression) if `astropy` reads it in the
     tests unchanged.
  3. Move to Git LFS (see Step 4) as a last resort.
- Run the affected tests (`photometry`, `tiltGeometry`, `imageStats`, `plateSolve`) and keep
  100 % coverage.

### 4. Policy for big data

Decision table (put into `../doc` and the review document):

| Kind | Policy |
|------|--------|
| Runtime data needed offline (`finals*`, `de440_mw4.bsp`) | stays in `../src/mw4/assets/data`, one copy, bumped via script `tasks.py`; wheel includes it |
| Large optional data (star catalogues, `hip_main.dat`, map shapefiles) | not tracked; generator scripts in `../src_add/generators` download from the source URL, results are small derived files that are tracked |
| Generated code/resources (`resources.py`, `*_rc.py`) | never tracked, built in CI/`../tasks.py` |
| Test images > 1 MB | cropped/compressed; otherwise Git LFS |
| Docs images | PNG ≤ 500 kB, optimise with `oxipng` before commit |

Git LFS is only introduced if Step 3 cannot get below the limit; LFS makes every contributor
and CI job install it, so it is the last resort for a hobby/pro-am project.

### 5. Shallow clones for CI and contributors

- CI: `actions/checkout` with `fetch-depth: 1` where history is not needed (lint, unit
  tests); keep full depth only for the release/changelog jobs.
- Contributor doc: `git clone --filter=blob:none` (partial clone) gives a working clone in a
  few MB without touching history. Add to `README`/`../doc/install`.
- Run `git gc --aggressive --prune=now` on the maintainer's clone once (no effect for others).
